# 产品概述

## 1. 产品愿景

**让每个人都值得被好好照料。**

在电影中，阿尔弗雷德做的不是替布鲁斯·韦恩解决一切，而是记住他的一切——生日、习惯、痛苦与热爱，然后在恰到好处的时刻递上一句提醒、一杯热茶。

Alfred 的产品愿景是成为你数字生活中的那位管家：**它了解你，记得小事、照顾大事，始终站在你这一边。** 它不是又一个`待办清单 App`，而是围绕你个人生活的、有记忆的、有情感的 AI 管家。

**而管家最自然的交互方式是「说话」** —— 像对真管家一样开口吩咐，而不是在屏幕前敲指令。语音输入从第一天起就是 Alfred 的第一等公民体验，而不是可选项。

**但打字永远可用。** 有些场合不方便说话——开会、地铁、安静的环境；有些习惯就是爱打字。Alfred 的输入条**一键切换语音 / 文本**，两种方式都走同一条理解管线。**默认首屏是语音输入**（呼应"开口即管家"），但用户可以进偏好设置，把默认输入改成文本。

**对话即产品，Alfred 本身才是重心。** 用户打开 Alfred，看到的是对话，用的是对话，一切能力都通过"对 Alfred 说"来实现——查询日程、确认记录、汇总账目，全在对话里完成。日程列表、记账本、记忆档案等管理界面**存在但刻意弱化**：它们只是让你偶尔检查、校对、修改的"后台"，永远不会喧宾夺主。

**Alfred 一直在你身边。** 这台应用启动即开始**持续聆听**——不需要先"唤醒"，更不是按键后才有耳——Alfred 一直在。它在听的同时持续判断：**哪些话是值得它弯腰的"真事"，哪些只是身边的"废话"**。

- **真事（要办的事）**：日程、待办、记账、提醒等"想委托给管家"的事项 → **轻声向用户确认**，确认后才执行；
- **该记下的**：用户没有要求记、但值得存档的信号——偏好（"我喜欢喝美式"）、家事、情绪——**静默记入记忆**，不打断当前动作；
- **废话**（闲聊、自言自语、环境声、无关内容）：不打扰、不记录、不触发任何动作，继续安静地倾听。

管家可以被"叫到"，但它更常是**一直在身边、知道哪句话值得弯腰**的那一位。

## 2. 目标用户

- **忙碌的职场人**：日程多、杂事碎，需要一个真正记得住他们生活上下文的助理。
- **注重健康与财务的个人**：希望规律记录体检、用药、收支，但不想自己维护繁琐台账。
- **需要陪伴的人**：希望有一个能听、能共情、又不会带情绪的树洞。
- **多设备用户**：办公用电脑、通勤用手机、在家用平板——管家要能在任何一块屏幕上"随叫随到"。
- **开发者与自托管用户**：对数据主权敏感、喜欢自部署的用户——Alfred 提供开源自托管版，能力不打折，只把"替官方服务器"换成"配自己的 Key / 自建服务"。

> 三端形态：**电脑（桌面端）、手机（移动端）、平板**，均为完整独立的应用；多端共享同一账号与数据。

### 2.1 双版本定位

| | **Community / 自托管版**（开源） | **Cloud / 大众版** |
|---|---|---|
| 定位 | 给懂技术 / 在意数据主权的用户：自部署、自己掌控 | 给大众用户：下载即用、傻瓜式 |
| 数据与账号 | 数据完全留本地；同步可选（自建 relay 或禁用） | 官方托管账号与同步，多端自动一致 |
| AI 能力 | 自带 LLM API Key，或接入本地模型 | 官方集成的 LLM / ASR，无需配置 |
| 安装 | 源码编译 / Docker 一键 | 应用商店 / 官网安装包 |
| 能力边界 | **与 Cloud 版完全对齐，零阉割** | 全量能力 + 官方维护便利 |

> **同源双发行**：两种版本共用同一套 Flutter 客户端与 `core/` 业务核心，能力不产生分裂；差异仅在**基础设施的提供方**——自托管版接您自己的服务，Cloud 版接官方服务。切换由配置决定，业务代码不复制。

## 3. 使用场景

### 场景 1：每日管家
早上打开 Alfred，它主动汇报：
- 今天有哪些日程 / 待办
- 天气与通勤建议
- 纪念日提醒（今天是妈妈的生日）
- 待续的健康提醒（该吃维生素了）

### 场景 2：随手吩咐（语音优先）
> 对着 Alfred 说："明早 7 点叫我起床并提醒我带护照，我 9 点的航班"
> "记一笔：今晚买菜花了 128 块"
> "把周三的健身取消，换到周四晚上 7 点"

Alfred 听懂你的话 → 决定下一步（去办 / 记下 / 回答）→ 写入对应的结构化条目 → 语音/文本确认。**所有动作可撤销。**

### 场景 2b：无痕口述
> 做菜时两手占着，直接说：”菜谱里加个可乐鸡翅，食材：鸡翅、可乐、生抽"
Alfred 在后台安静地记录，不打断你手上的事。

### 场景 2c：想说就说，想打就打
> 开会时不方便开口，点一下输入条切成**文本**："三点把方案发我邮箱"
> 回到家想快点，输入条一键切回**语音**，直接说就行
> 习惯打字的人，进偏好设置把默认输入改成文本——以后打开 Alfred 首屏就是文本输入条

语音和文本在 Alfred 里是同一个入口的两种模式，随时切换，理解效果一致。

### 场景 3：它就懂
> "我最近压力好大"
> Alfred：识别到情绪信号 → 不急着给建议，先共情 → 简单记录情绪 → 主动跟进
> "我这个月的支出是不是超了？"
> Alfred：查账 → 行程化总结 → 温和建议

### 场景 4：管家该记住的
> 用户中途随口一句："我奶奶喜欢喝龙井，下周去看她带这个"
> 不打断对话，Alfred 异步记入记忆档案 → 下周四约会前主动提醒你带茶。

### 场景 5：在每块屏幕上都是管家
> 电脑上做项目时：Alfred 桌面端悬浮侧边栏，随手吩咐、查日程。
> 通勤路上：掏出手机对 Alfred 说"把今晚的健身取消"，它记得你在电脑上排的日程。
> 回家用平板：横屏看今天的日程总览大卡片，或对着平板说"明天飞去上海，帮我记好航班提醒"。

**同一位管家，三块屏幕，一份记忆。** 无论在哪端创建、修改的数据，其他端自动同步，无需手动迁移。

### 场景 6：什么都在对话里
> 用户从不去翻"日程页"或"记账页"，而是直接问：
> "我这周有什么安排？" → Alfred 报日程
> "昨天随礼的钱记了吗？" → Alfred 翻出账目核对
> "我的购物清单里还有啥？" → Alfred 念出清单
> 打开 Alfred 永远是同一个动作——**对管家说话**；管理界面只在需要"人工校对"时打开。

### 场景 7：一直在身边的管家
> 早上开电脑，Alfred 已经在听。你一边洗漱一边随口说"今晚给妈妈打电话"。
> → 它没打断你，先轻声确认："要记一笔'今晚给妈妈打电话'吗？"你回"嗯"——确认后记入日程。
>
> 中午同事在旁边说笑，你自言自语"该去买瓶水了"——废话，它安静不打扰，不记录。
>
> 下午开会你随口"这个客户喜欢喝毛尖"，没要求记——它**静默吸收**进记忆档案，下次安排自然用上。
>
> 深夜你叹气说"最近好累"，它不打断，默默记下情绪信号，之后再关心一句。

**区别对待，正是管家的判断力。** 该确认的确认，该记下的记下，该忽略的忽略——Alfred 为你省下的不是"操作"，而是"决定"。

## 4. 核心价值主张

| 价值 | 说明 |
|------|------|
| **随叫随到** | 语音优先：开口即管家，无需打字、无需找按钮 |
| **想说就说，想打字就打** | 输入条一键切换语音/文本；默认语音首屏，偏好可改为文本优先 |
| **一直在身边** | 开机即持续聆听 —— 无需先唤醒，像真管家一样守候 |
| **会判断** | 自动分辨真事 / 该记的 / 废话：该确认的确认、该记的记下、废话忽略 |
| **对话即中心** | 一切能力通过对话完成；查询、记录、汇总都在跟 Alfred 对话里，不用学界面 |
| **记得住** | 长期记忆系统构建持续的用户档案，跨对话记住偏好与承诺 |
| **靠得住** | 日程/提醒/记账等核心动作走结构化执行，可靠、可撤销 |
| **懂情绪** | 冲突时的共情与情绪看护，不止于任务执行 |
| **少打断** | 只在必要的时刻轻声确认或提醒，默认不轰炸 |
| **三端皆在** | 电脑 / 手机 / 平板都有完整管家；一个账号、一份记忆、自动同步 |

## 5. 非目标（明确不做）

- ❌ 不做仓库级全球单机：**三端是「同一账号不同端」，不是「每台设备各自为政」**（数据不互通）
- ✅ **常驻聆听是核心体验，但必须透明可控**：启动即持续聆听（用户可选择关闭）；常驻「聆听中」可见指示；一键闭麦；录音仅在本地转写、识别后即弃，不上传原始音频
- ❌ 除非用户显式授权，不监听相机 / 屏幕
- ❌ 不做社交代理（替用户发消息、点赞等内容分发）
- ❌ 不把"真事判断"变成拦截器：废话不打断、不记录、不做任何动作；除非需要确认，否则不发声
- ❌ 不做医疗诊断 / 法律建议等结果性专业服务
- ❌ 不为变现优化内容，绝不诱导消费或推销
- ❌ 不让功能页喧宾夺主：**主界面永远是对话**，日程/记账/档案等管理界面维持必要的"后台"定位，不引导用户泡在功能页里
- ❌ 双版本不制造能力分裂：Community 自托管版与 Cloud 版共享代码与能力，**不人为阉割功能做差异化**（差异化只在"基础设施由谁提供"）

## 6. 商业模式（初步设想，非本期重点）

订阅制 + 高阶服务（多设备、云端同步、深度记忆、扩展能力包）。本期聚焦体验。

- **Cloud 版**：付费订阅，官方提供账号 / 同步 / AI 托管，傻瓜式体验直接变现
- **Community 自托管版**：开源免费，能力与 Cloud 对齐；作为生态与信任入口，同时吸引开发者贡献
- **License**：**待定**（倾向 AGPL-3.0），既允许自托管，又保护 Cloud 商业版核心

## 7. 成功指标

- 连续使用：核心用户 >70% 留存（周活/月活）
- 记忆准确性：被用户纠正/遗忘的比例
- 提醒可信度：漏提醒率 = 0
- 情绪价值：用户对主动共情的评分
- **语音激活率**：日常使用中语音/文本交互占比 >50%
- **真事判断质量**：需要处理的真实委托召回率 >95%，废话误判率 <2%（该打断却没打断 / 不该打断却打断）
- **三端同步**：账号下设备间数据一致的误差率（冲突率 < 0.1%）
