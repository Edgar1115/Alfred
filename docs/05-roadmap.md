# 开发路线图

> 原则：**先做对一件核心闭环，再做全方位**。每个里程碑都可独立运行、可验证、可回滚。三端共享一套代码基座。

## M0 项目脚手架 & Flutter 三端骨架

**目标**：项目能跑起来，三端都有可运行壳。

- [x] 项目文档（本文档即产物之一）
- [ ] Flutter 项目初始化（全平台：iOS / Android / macOS / Win / Linux）
- [ ] **对话主界面骨架**：启动即对话（输入栏 + 语音按钮），对话为唯一一等页面
- [ ] 响应式 UI 骨架：断点布局（phone / tablet / desktop），`SafeArea` + 横竖屏；管理页仅占位
- [ ] 持久层：SQLite 抽象（drift）+ 迁移脚本
- [ ] LLM Provider 抽象（本地/远程 mock）
- [ ] 语音层骨架：`SpeechToTextProvider` + 常驻聆听（VAD + mock 转写）+ 一键闭麦 / 聆听指示
- [ ] **价值分层骨架**：`classify` 模块 + 委托确认状态机（mock 判定）
- [ ] 日志与配置
- [ ] `core/` 目录结构与纯 Dart 单测脚手架
- [ ] 双发行骨架：`cloud` / `community` flavor + Provider 注入抽象（LLM / 同步点）

**验收**：三端都能启动，**首页始终是对话主界面**（且出现「聆听中」指示、可一键闭麦）；跑的 `alfred run` 能接收文本（mock 语音）并 echo；写读 SQLite 通过；`--dart-define=ALFRED_MODE=cloud|community` 能构建两种 flavor 包。

## M1 核心闭环：日程与提醒（P0）+ 语音

**目标**：让"管家"第一件事靠谱 —— **提醒真的会被执行，且用语音能创建**；查询在对话里完成；**常驻聆听 + 价值判断跑通**。

- [ ] 日程技能：CRUD + 重复事件 + 提醒偏移
- [ ] 自然语言解析：语音/文本 `明晚7点健身房` → Schedule（LLM + 校验兜底）
- [ ] 本地提醒调度器（平台原生通知）
- [ ] 执行前确认 + 撤销（对话内完成，不跳表单页）
- [ ] 零漏触发（启动补发）
- [ ] 语音输入闭环：常驻聆听 + 本地 Whisper + VAD → **classify 分层** → 委托确认 / 吸收记忆
- [ ] **委托确认闭环**："明早 8 点提醒吃药" → 轻声确认 → 确认后建日程（未确认不落库）
- [ ] **吸收与忽略**："奶奶喜欢龙井" 静默入记忆；闲聊废话不打断不记录
- [ ] **对话内查询**："我下周有什么安排" → 对话卡片返回，不跳列表页
- [ ] 平板/桌面/手机三种尺寸 UI 都覆盖对话主界面 + 日程查询

**验收（User Story）**：
> 手机按住说"明早 8 点提醒我吃药" → 次日 8:00 收到通知 ✅
> 电脑端"周五 18:00 取消健身" → 取消并确认 ✅
> 平板横屏问"我明天有什么安排" → 卡片直接给出日程 ✅
> 开机后没说"Hey Alfred"直接说"明早 7 点提醒去医院" → 常驻聆听捕获 → 轻声确认 → 建日程 ✅
> 旁边人闲聊"今天菜不错" → 完全无反应，不记录不打断 ✅
> 追尾说"我最近压力好大" → 静默记情绪，不打断 ✅
> 用户全程没离开对话页 ✅

## M2 账号 + 多端同步（P0）

**目标**：Alfred 是三端一管家，数据流动起来。

- [ ] 账号系统（注册/登录/设备注册）
- [ ] oplog 变更捕获 + 上传/拉取
- [ ] 冲突解决（LWW + tombstone）
- [ ] 云端 relay 服务（轻量）
- [ ] 离线队列 + 网络恢复自动同步
- [ ] 多设备登录同账号后自动合并

**验收**：
> 手机新增日程 → 同一账号的平板自动出现 ✅
> 平板删除日程 → 手机尊重删除（tombstone 生效）✅
> 飞机模式期间在手机记一笔 → 开网后电脑出现该条 ✅

## M3 长期记忆与用户档案（P0）

**目标**：Alfred 开始"记住你"。

- [ ] Memory 技能：增删改查 + 语义检索（向量 + 摘要）
- [ ] 对话中自动抽事实（"我喜欢喝美式"）→ 归档
- [ ] 记忆修正（`忘记...` / `记住...`）
- [ ] 上下文注入每次对话
- [ ] 语音唤醒词（"Hey Alfred"）+ 静音自动切断
- [ ] 记忆参与同步（多端共享档案）
- [ ] **对话内查记忆**："我奶奶喜欢喝什么茶" → 对话卡片返回，无需打开档案页

**重要约束**：记忆可查看、导出、清空（清空走 tombstone 同步）。查看入口为二级后台页，不做主导航。

**验收**：
> 对话说"我喜欢喝美式" → 隔天问"我喝什么咖啡" → 回答正确 ✅
> "我不喜欢美式了" → 更新而非叠加 ✅
> 平板 Pro 上唤醒说"明天下午提醒交方案" → 全端可见 ✅

## 风险清单

| 风险 | 缓解 |
|------|------|
| LLM 时好时坏 | 核心动作 LLM + 规则双重校验；不依赖模型做执行 |
| 提醒漏触发 | 本地调度器 + 启动补发；错误指标可追踪 |
| 多端同步冲突 | LWW/墓碑；冲突可查询；先本地一致再同步 |
| 语音识别错误 | 关键操作语音复述确认；可语音纠正 |
| **误判（把废话当真 / 把真事当废话）** | 真事确认后才执行；误判可回滚；吸收可删；`listen_audit` 追踪调优 |
| **常驻聆听功耗** | VAD 低功耗门控（非说话不 ASR）；极小本地模型；后台节电策略 |
| **常驻监听隐私敏感** | 透明「聆听中」指示 + 一键闭麦 + 本地转写即丢弃 + 可完全关闭常驻聆听 |
| 平台差异 | Flutter 一套代码，但各平台系统通知/权限差异需单独测 |
| 功能页抢镜头 | 对话优先是硬约束：所有界面评审检查「是否有人能离开对话主界面去做本可对话完成的事」 |
| 记忆幻觉 | 记忆可查询、修正、关闭 |
| 隐私 | 本地优先 + 端到端加密（P2）；导出/清空一键 |
| **双版本能力分裂** | 共享 `core/` + Provider 注入是硬约束；社区版不自建"阉割"；评审检查是否在两端保持能力对齐 |
| **自托管部署门槛** | Docker 一键 + 文档 + 示例配置；优先保证"仅配环境变量即可跑" |
| **开源与商业冲突** | License 待定（倾向 AGPL-3.0）+ 双发行边界声明（能力零分裂，商业仅卖托管服务） |
